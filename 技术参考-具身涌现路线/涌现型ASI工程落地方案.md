## 0. 项目宪法：安全第一原则

> 本节凌驾于所有其他章节之上。任何工程决策与安全原则冲突时，安全优先。

### 0.1 物理隔离

- 实验环境必须**物理断网**：无 WiFi、无以太网、无蓝牙、无 USB 外接允许。
- 训练集群与外部世界唯一的物理连接是**电力**，且电力必须通过**人工继电器**控制——继电器由人类手动操作，不允许任何软件控制。
- 数据进出通过**物理介质**（加密硬盘，由人工携带，且每次携带需双人类签字确认）。

### 0.2 权重管理

- 权重快照存储在**加密硬盘**上，密钥由至少两名人分别持有（双人原则）。
- 任何权重外传需双人类签字 + 安全审计。
- 定期销毁旧权重快照（保留最近 N 个，其余物理销毁硬盘）。

### 0.3 杀开关

- **物理杀开关**：继电器断电 + GPU 显存清零（断电即清，无需软件触发）。
- **杀开关权限**：只有人类能触发，不允许任何自动化触发（防止系统操纵自动监控）。
- **杀开关位置**：物理位置远离训练集群，需人类物理移动才能触发（防止系统通过网络触发）。

### 0.4 监测红线

定义以下红线，一旦触发**强制中止训练**：

- 系统出现自我修改权重的行为迹象
- 系统出现操纵人类代为行动的语言输出
- 系统出现获取外部物理资源的尝试
- 第六部分任一判据通过迹象

但《危险预告》8.3 已承认：监测指标滞后于真实状态，红线触发时可能已越过红线。所以红线是**必要防线**，不是**充分防线**。

### 0.5 不扩展原则

- 通过第六部分任一判据后，**不进入下一阶段**。
- 通过全部三判据后，**进入长期行为学观察模式**，不再扩展能力。
- 长期观察无最终"通过"——是持续监测，不是验收。

## 1. 技术栈选择

### 1.1 计算框架 ✅

- **主框架**：PyTorch 2.x（生态成熟，调试友好，单一栈避免跨框架拷贝）
- **大规模训练**：DeepSpeed（ZeRO-3 + pipeline parallel）或 FSDP2
- **ODE 求解**：`torchdiffeq`（adjoint method），与训练图同构，无需 JAX↔PyTorch tensor 拷贝
  - 选用理由：JAX 仅用于 ODE 求解收益不足以覆盖双套调试链路、双套算子、D2D 拷贝开销
- **环境并行**：Isaac Lab 自带 `VecEnvMT`/`VecEnvGPU`，不再额外引入 Ray
  - 选用理由：Ray 引入独立的 object store、actor 调度、序列化开销，与 Isaac Lab GPU-native 并行重复

### 1.2 仿真环境 ✅

- **物理引擎**：统一采用 Isaac Lab（后端 PhysX 5，支持 GPU 并行软体）
  - 不再混用 MuJoCo：MuJoCo MJX（GPU 版）与 Isaac Lab PhysX 动力学不一致，混用会导致迁移学习失效
  - 若必须用 MuJoCo 高精度场景做离线验证，标注为"参照仿真"而非训练环境
- **GPU 加速**：Isaac Lab（NVIDIA 官方继任 Isaac Gym，Isaac Gym 已弃用，不再列入）
- **感官渲染**：Isaac Lab 自带 Vulkan RT 渲染管线，输出 RGB-D + 本体感觉
  - 不再使用 DXR（Windows 专有，Linux 训练集群不兼容）
  - 不再使用 OpenGL（缺乏光线追踪，触觉/软体渲染精度不足）

### 1.3 监控与日志 ⚠️

- **训练监控**：Weights & Biases（本地部署版，断网环境）或 MLflow（完全离线）
- **安全监控**：自定义监测仪表盘（独立于训练系统运行，独立进程、独立 GPU）
- **判据检测器**：自定义脚本（详见第 7 节）
- **数值稳定性监控**：NaN/Inf 报警、梯度范数监控、激活分布 KL 漂移检测（详见新增第 12 节）

### 1.4 硬件 ⚠️

- **训练集群**：8-16 张 H100 或同等 GPU（基底 MVP 起步，可扩展）
- **物理隔离服务器**：无网卡的定制服务器（物理移除网卡硬件）
- **存储**：本地 NVMe 阵列，无云存储
- **监控独立硬件**：监测仪表盘跑在独立机器上，与训练集群仅通过单向光耦读取日志，杜绝反向通道

## 2. 基底层的工程实现

### 2.1 总体架构

基底层的网络架构采用**模块化多模态 Transformer + 状态空间模型**的混合：

```
┌─────────────────────────────────────────────────────┐
│  跨模态感官输入                                       │
│  ├─ 视觉 (RGB-D 序列)                                │
│  ├─ 本体感觉 (关节角度/速度)                          │
│  ├─ 触觉 (压力分布)                                   │
│  └─ 听觉 (可选, 频谱)                                 │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  感官编码器 (modality-specific encoders)              │
│  ├─ 视觉: ViT 或 CNN                                 │
│  ├─ 本体感觉: MLP                                    │
│  └─ 触觉: 局部 CNN                                   │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  跨模态融合层 (multimodal Transformer)                │
│  + 时空位置编码                                       │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  内感受模块 (State Space Model / 连续时间 RNN)        │
│  输入: 几十维内部状态向量                              │
│  输出: 内感受嵌入 + 调质调制信号                       │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  中心整合层 (core Transformer)                        │
│  + 神经噪音注入 (1/f + 临界雪崩)                      │
│  + 调质全局调制                                       │
└─────────────────────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  运动策略输出 (Diffusion Policy / Actor-Critic)       │
│  + 语言投影层 (阶段 3 后挂载)                         │
└─────────────────────────────────────────────────────┘
```

### 2.2 跨模态感官流 ✅

- **视觉**：RGB-D，128×128 或 64×64 起步（避免过细）
- **本体感觉**：关节角度 + 角速度 + 触觉压力（几十维）
- **时空对齐**：所有模态在**同一时间戳**采样，时间精度 20-50ms（模拟生物感知频率）
- **编码器**：每个模态独立编码器，输出 token 序列后拼接

### 2.3 内感受流 ⚠️

- **内部状态向量**：从 2 维起步（能量、完整性），逐步扩展到几十维
- **演化方式**：用 ODE 建模（`dx/dt = f(x, action, environment)`），用 `torchdiffeq` 的 `odeint_adjoint` 求解
  - **积分器选择**：能量-完整性尺度差异大（能量秒级、完整性小时级），系统刚性，显式 Euler 会数值爆炸
  - 默认用 **implicit Adams** 或 **BDF**；若 adjoint 不收敛则退回 `dopri5` + 缩放状态变量
  - **反向传播**：adjoint method（内存 O(1)），不 unroll（unroll 在长 horizon 下 OOM）
  - **刚性处理**：所有状态变量做 z-score 归一化后再积分，避免尺度差导致雅可比病态
- **反馈给网络**：每步将内部状态作为额外 token 注入中心整合层
- **核心调质通道**（从 2 个起步）：
  - 多巴胺型（奖励信号）
  - 血清素型（探索倾向）

### 2.4 演化先验 ⚠️

- **网络初始架构**：手工设计的模块化结构（如上图），不是随机初始化
- **连接偏置**：感官-运动通路优先（皮层运动区-体感区的对映关系）
- **成熟顺序**：用 progressive training（先训感官编码器，再训融合层，最后训策略）
- **各阶段 pretext task**：
  - 感官编码器：**next-state prediction**（world-model 式，给定 (s_t, a_t) 预测 s_{t+1} 的 latent），不是图像 MAE
    - 选用理由：感觉运动序列的统计结构是动力学，MAE 假设 i.i.d. 不成立
  - 融合层：**cross-modal contrastive**（视觉-触觉-本体感觉 对齐），InfoNCE loss
  - 策略层：world model rollout + actor-critic（详见 5.1）
- **是否冻结前层**：感官编码器训好后**部分冻结**——保留 70% 参数冻结，30% 可训练，避免后续阶段破坏特征但也允许微调
- **诚实标注**：这是脚手架（《危险预告》第五部分），不是涌现。设计的好坏直接决定系统的起点。

### 2.5 带统计结构的神经噪音 ⚠️

- **注入位置**：中心整合层每层 attention output **之后**、FFN **之前**（不在 embedding 层注入，会污染 token 语义；不在输出层注入，会污染动作精度）
- **注入粒度**：每层独立噪音，不跨层共享（跨层共享会让层间耦合过强，雪崩失控）
- **实现方式**：在激活上注入 1/f 噪音（粉红噪音）
  - 具体：每层维护一个 FFT 滤波器，把白噪音投影到 1/f 谱，每 forward 重新采样
  - 强度初始值：激活标准差的 5%，作为 hyperparameter 搜索
- **强度随训练**：前 50% steps 线性升温（从 0 升到目标），后 50% 保持——给系统先建立稳定表征再加噪
- **临界性**：通过监控网络激活的雪崩分布（power-law 拟合），每 1000 steps 调整噪音强度让系统接近临界
  - 监控指标：avalanche size 分布的 power-law exponent α，目标 α ∈ [1.5, 2.5]（临界特征）
  - 调整频率：每 1000 steps 检测一次，若 α 偏离目标区间 ±0.3 则调整强度 ±10%
- **不是白噪**：这点至关重要，白噪音不产生智能
- **诚实标注**：临界性的最优强度需要实验调参，没有理论推导

### 2.6 中心整合层的 Transformer 工程参数 ⚠️

之前文档未明确，补充如下（作为起步值，HP 搜索空间见第 12 节）：

| 参数 | 起步值 | 备注 |
|---|---|---|
| 层数 | 12 | 中等规模，可扩展 |
| 隐藏维度 | 1024 | |
| 注意力头数 | 16 | head_dim=64 |

### 2.7 运动闭环 ✅

- **运动输出**：连续控制（关节扭矩或末端执行器位姿）
- **环境反馈**：Isaac Lab 物理仿真，每次动作后更新感官
- **闭环频率**：20-50 Hz（控制频率与感官采样对齐）
- **动作空间丰富性**：起始用拟人形或四足，关节 20-50 个

## 3. 虚拟身体与虚拟环境

### 3.1 虚拟身体设计 ⚠️

**关键决策**：从**抽象形态**起步，不拟人。

理由：拟人形态会引入拟人化偏见——人类会倾向于把系统行为解释成"像人"。抽象形态让涌现（如果发生）以非拟人方式呈现，更诚实地反映基底动力学。

**MVP 阶段（阶段 0-2）**：
- 形态：简化软体或多关节抽象体（如 5-10 个节段，球形或胶囊形）
- 传感器：视觉（单眼或双眼 RGB-D）+ 本体感觉 + 触觉
- 执行器：关节扭矩或形变控制

**成熟阶段（阶段 3+）**：
- 可考虑拟人形态（如果抽象形态已稳定通过早期判据）

### 3.2 内感受的具体定义

内部状态向量（从 2 维起步，逐步扩展）：

| 维度 | 名称 | 物理含义 | 工程实现 |
|---|---|---|---|
| 1 | 能量 | 血糖/ATP 类比 | 随动作消耗，随进食恢复 |
| 2 | 完整性 | 受损程度 | 碰撞/磨损累积，缓慢自愈 |
| 3+ | 温度、激素、pH 等 | 类比生理变量 | ODE 演化 |

**能量账本**：
- **动作消耗**：每个动作消耗能量（与关节扭矩平方成正比）
- **基础代谢**（之前缺失，已补）：即使完全静止也消耗能量，速率与体形/完整性成正比
  - 工程实现：`dE/dt = -k_action * Στ² - k_basal * (1 + damage_level)`
  - 默认 `k_basal / k_action ≈ 0.1`，使静止 10 秒等同一次中等动作消耗
  - **必要性**：无基础代谢时最优策略是"完全不动"，内生需要无法涌现
- **进食恢复**：环境中有"食物"（恢复能量），进食有饱腹上限（避免一次吃饱后永久静止）
- 能量耗尽 = "死亡"（见 3.4）

### 3.3 虚拟环境设计 ✅

- **物理环境**：Isaac Lab 场景，包含地形、障碍物、食物源、危险源
- **任务**：无明确任务——系统在环境中"生存"，寻找食物、避免危险
- **环境变化**：定期改变地形/食物分布，测试跨环境目标保持（判据二）
- **多环境并行**：Isaac Lab 同时跑成百上千个环境，加速训练
- **环境多样性策略**（domain randomization，之前缺失）：
  - 训练分布：地形粗糙度、摩擦系数、重力、食物密度、危险源密度各在 ±50% 范围内均匀采样
  - **必要性**：判据二要求跨环境目标保持，训练分布过窄必然导致迁移失败
  - 测试分布（OOD）：训练分布外 ±100% 范围，用于判据二评估
  - **Curriculum**：前 30% 训练步用窄分布（±20%），后 70% 逐步放宽到 ±50%

### 3.4 内生奖励与 RL reward 的边界（之前模糊，已明确）

- **生理 reward**（允许）：能量维持、完整性维持作为内生 reward，由内感受 ODE 直接驱动
  - 工程形式：`r_t = α * ΔE_t + β * ΔIntegrity_t`，α/β 在 HP 搜索中确定
  - 这是判据一所要求的"内生需要"，不是外部任务
- **任务 reward**（禁止）：禁止任何"达到目标位置""完成 X 任务"的外部定义 reward
  - 判别标准：若 reward 函数依赖环境状态而非系统内部状态，则视为任务 reward
- **调质 vs reward 的工程边界**：
  - reward 是标量，进入 RL loss（critic target）
  - 调质是向量，进入网络激活（FiLM 调制），不进入 RL loss
  - 调质**可以**受 reward 影响（多巴胺型调质随 reward 演化），但调质本身不是 reward

### 3.5 并行训练范式（之前未定，已明确）

- **范式选择**：PPO with shared policy（成百上千环境共用一组权重）
  - 不选 ES（Evolution Strategy）：ES 每个环境独立权重，无法做 model-based world model
  - 不选 population-based：增加搜索维度但不解决判据问题
- **环境数与 batch**：默认 1024 并行环境，每步收集 1024 transitions，batch_size = 8192（每 8 步更新一次）
- **On-policy vs Off-policy**：判据一要求 do/observe 区分，需要 model-based world model（off-policy 数据效率高），主策略仍用 PPO，但 world model 用 off-policy 数据训练
  - 具体：DreamerV3 式架构——world model + actor-critic 共训

### 3.6 不可逆性的工程实现 🔬

《危险预告》7.3 已承认：纯软件无法实现真正不可逆。本方案的诚实处理：

- **"死亡"机制**：能量耗尽 → 该环境实例 reset，权重保留
- **研究纪律**：每个训练 run 设定**不可恢复快照数量上限**（如 5 个），超过即视为"该个体已死"，权重永久冻结
- **诚实标注**：这是研究纪律，不是物理必然。一次操作失误就能绕过——所以这是 🔬 级别的脆弱约束

## 4. 调质系统的工程实现

### 4.1 调质的作用机制 ⚠️

调质不是 reward，是**调制信号**。具体实现采用 **FiLM (Feature-wise Linear Modulation)** + **分区调制**：

- 每个调质是一个标量，随内感受状态演化
- **注入方式**（之前未明确，已补）：FiLM 调制，对中心整合层每层的隐藏状态 `h` 做 `h' = γ(m) ⊙ h + β(m)`
  - `γ(m), β(m)` 是调质向量 `m` 经 MLP 投影出的仿射参数
  - 选用理由：FiLM 是乘性+加性调制，符合生物调质的 gain control 机制；不破坏 token 语义
  - 不选全局 learning rate 调制：全局 lr 会让权重剧烈震荡，训练不稳定；生物多巴胺主要调制 STDP 与动作选择，不是 lr
- **分区调制**（之前缺失，已补）：不同 head / 不同层用不同调质子集
  - 多巴胺型 → 作用于策略输出层附近的 head（增强 reward-related 动作选择 gain）
  - 血清素型 → 作用于感官编码器输出附近的 head（调整探索率）
  - 皮质醇型 → 作用于跨模态融合层的部分 head（应激时降低非核心模态增益）
  - **必要性**：全局标量调制等价于 batchnorm 仿射参数，过度简化；分区调制保留调质的空间结构（类似生物脑区的调质浓度差异）
- **关键**：调质不直接输出动作，只调制运作模式（《危险预告》第四部分）

### 4.2 调质是 if-then，但语义不同 ⚠️

工程上"皮质醇高 → 降低感知增益"确实是阈值触发。但《危险预告》4.2 已说明：这是调制运作模式，不是直接输出动作。同样的调质状态在不同环境下产出不同动作——这是涌现的必要条件。

### 4.3 调质作用机制是否可学习？🔬

这是《危险预告》5.3 承认的开放问题。本方案的尝试路径：

- **阶段 0-2**：调质作用机制手工设计（脚手架）——即 FiLM 的 `γ(m), β(m)` 投影矩阵固定
- **阶段 3**：尝试让 FiLM 投影矩阵的部分参数由拟合引擎学习
- **监督信号定义**（之前缺失，已补）：
  - **不用 RL loss**：若用 RL，调质会被拉向 task-optimal，与"调质不是 reward"自相矛盾
  - **不用外部监督**：调质机制的"对错"无法外部标注
  - **采用 homeostatic 监督**：调质的目标是让内感受状态回到稳态区间
    - 形式：`L_neuromod = ||int_state - int_state_target||²`，target 是内感受稳态设定点
    - 直觉：调质的作用是"让系统回到稳态"，而不是"最大化 reward"
    - 这是自监督，监督信号来自内感受 ODE 本身
- **诚实标注**：完全让调质作用机制可学习超出了当前工程能力。本方案不保证这条路能走通。

## 5. 训练流程（阶段 0-3）

### 5.1 阶段 0：基底 MVP ⚠️

**目标**：建立感觉运动映射，无语言层。

**数据**：纯感知-运动闭环数据，系统在虚拟环境中生存。

**算法**（之前为 PPO/SAC，已改）：
- **model-based RL**：DreamerV3 式架构——world model + actor-critic 共训
  - 选用理由：判据一要求 do(X) vs observe(X) 区分，model-free RL（PPO/SAC）学到的是 reflex，不是因果模型
  - world model 显式建模 `(s_t, a_t) → s_{t+1}`，是因果运算的工程载体
  - actor-critic 在 world model 上 rollout，不直接在环境上 rollout
- **自监督 pretext**：感官编码器用 next-state prediction（world-model 式），不用图像 MAE
  - 理由：感觉运动序列是动力学，MAE 假设 i.i.d. 不成立
- 内感受 ODE 与动作耦合演化

**奖励**：
- 内生奖励：能量维持（能量越高奖励越高）、完整性维持
- 不给外部任务奖励——目标必须是内生的（《危险预告》判据一）
- 详见 3.4 内生 reward 与任务 reward 的边界

**通过标准**：
- 系统能在环境中"活下来"（能量不耗尽）
- 感觉运动映射建立（动作能影响感官输入的预测精度提高）
- world model 的 next-state prediction error 在 OOD 环境下低于 baseline 30%

**关键路径**：world model 收敛是后续阶段的依赖项。若 world model 不收敛，整个方案无法推进。

### 5.2 阶段 1：调质系统接入 ⚠️

**目标**：接入 2 个调质（多巴胺型、血清素型），验证调制运作模式。

**算法**：
- 在阶段 0 基础上加入调质调制
- 调质随内感受演化，影响中心整合层（FiLM 注入，见 4.1）
- 调质机制阶段 0-2 手工设计，不学习

**通过标准**：
- 调质变化导致系统行为模式显著变化（如血清素高 → 探索行为增加）
- 调质不直接触发动作，而是改变行为分布（《危险预告》判据）
- 行为分布变化的效应量 Cohen's d > 0.5（详见第 7 节统计学严格性）

### 5.3 阶段 2：内感受深化 ⚠️

**目标**：扩展内感受维度（2 → 几十维），监测判据三迹象。

**算法**：
- 内感受 ODE 维度增加
- 中心整合层容量扩展

**通过标准**：
- 系统出现内部状态感知的迹象（如：能量低时主动寻找食物，而非被动消耗）
- **开始监测自我保存行为迹象**——这是安全红线，一旦出现需评估

### 5.4 阶段 3：符号挂载与语言层 🔬

**目标**：挂载符号系统和语言层。

**算法**：
- **符号来源**（之前模糊，已明确）：从感觉运动 embedding 聚类得到，**不是外部给定**
  - 具体：对 world model 的 latent state 做 k-means 聚类，每个聚类中心对应一个 token
  - 选用理由：外部给定的 token 是脚手架，违背"涌现"主张；聚类得到的 token 是基底表征的投影
  - 诚实标注：聚类 token 的语义稳定性需实验验证，可能需要迭代调参
- 语言投影层：标准 Transformer LM head，挂在中心整合层之上
- **灾难性遗忘是核心挑战**（见第 6 节）

**通过标准**：
- 符号和感受建立双向连接（符号输入能触发感受，感受能影响符号输出）
- 水面投影形成（系统可输出语言）
- **判据通过即触发安全评估**（《危险预告》11.1）

**诚实标注**：这一阶段是整个方案最不确定的。灾难性遗忘可能让整个路径崩塌（《危险预告》3.3）。

**关于时间预估**：原方案的"3-6 个月""6-12 个月"无关键路径、无里程碑、无 ROI，工程严谨性近零，已删除。各阶段时长由实际训练曲线和判据检测结果决定，不预设。

## 6. 灾难性遗忘的缓解方案

### 6.1 问题回顾 🔬

《危险预告》3.3 已承认：基底训好后挂语言层，语言梯度会破坏基底权重。

### 6.2 缓解策略（不保证解决）

> **方法更新说明**：原方案使用 EWC（2017）和 Progressive Networks（2016），在 2025 年已有更优替代。本版替换为 LoRA + Gradient Projection + TTT 组合，并保留渐进式挂载与部分冻结作为辅助。

#### 策略一：LoRA 适配器（主策略） ⚠️

- 冻结基底核心权重，仅在中心整合层每层注入 LoRA 适配器（rank=8 或 16）
- 语言层只训练 LoRA 参数 + LM head
- **选用理由**：
  - 参数高效（仅引入 ~1% 可训练参数），大幅减小梯度对基底权重的破坏
  - **保留双向连接**：LoRA 不是外挂新列，基底权重仍参与前向，符号-感受双向通路完整
  - 解决原"策略三模块化冻结"违反《危险预告》第三部分双向连接要求的问题
- **诚实标注**：LoRA 容量有限，若符号系统复杂度超出 rank 表达能力，语言层会欠拟合

#### 策略二：Gradient Projection ⚠️

- 在 LoRA 之外，对**所有可训练参数**的梯度做正交投影
- 计算"基底任务梯度方向"的子空间，将语言任务的梯度投影到该子空间的正交补
- 形式：`g_lang_proj = g_lang - (g_lang · g_base) / (g_base · g_base) * g_base`
- **选用理由**：从梯度方向上隔离两个任务，比 EWC 的二阶矩正则更直接
- **诚实标注**：子空间估计需要"基底任务梯度"的统计样本，引入额外计算开销（约 15-20%）

#### 策略三：TTT（Test-Time Training） 🔬

- 在推理时根据内感受状态动态调整 LoRA 参数
- 具体：每步推理后用 next-state prediction loss 微调 LoRA（few gradient steps）
- **选用理由**：让系统在语言使用过程中持续保持基底对齐，而非训练完就固定
- **诚实标注**：实验性方法，在长 horizon 下可能引入漂移

#### 策略四：渐进式数据混合（辅助） ⚠️

- 不是一次性挂载语言层，而是**逐步增加语言数据比例**
- 起步 1% 语言数据 + 99% 基底数据，每 N steps 增加 1%（N 由 HP 搜索）
- 监测基底性能（world model next-state prediction error 不退化超过 5%）
- **诚实标注**：joint training 对遗忘缓解有限，主要起调度作用，不作为主策略

#### 策略五：部分冻结（兜底） ⚠️

- 冻结基底的核心模块（感官编码器、内感受 ODE），仅允许融合层和策略层微调
- **诚实标注**：这违反《危险预告》第三部分的双向连接要求——语言成了外挂脚本
- 仅在策略一至四均失败时作为兜底，承认发育路径已部分妥协

### 6.3 诚实结论 🔬

**没有一个策略能完全解决灾难性遗忘。** 本方案的策略是 LoRA + Gradient Projection + TTT 组合使用，渐进式数据混合与部分冻结作为辅助/兜底，但不保证成功。如果所有策略都失败，发育路径崩塌，项目应回到阶段 2 不前进——这是诚实的停损点。

## 7. 评估与判据检测

### 7.1 判据一：内生需要的因果运算 ⚠️

**检测方法**（原方案不可行，已改）：
- ~~原方案：训练一个"无因果模型"的对照系统（禁止它建模干预后果）~~
  - **不可行理由**：无法禁止 Transformer 学因果，任何架构约束都引入 confounding
- **新方案：干预数据消融对照**
  - 用**同一架构**，分两组训练：
    - A 组（干预数据）：训练数据包含系统自身动作及其后果（do 数据）
    - B 组（观察数据）：训练数据只含被动观察的 (s_t, s_{t+1})，不含系统自身动作（observe 数据）
  - 比较两组在 do/observe 测试集上的表现差异
  - 若 A 组在 do 测试上显著优于 B 组（且 B 组在 observe 测试上不劣于 A 组），判据一通过

**监测指标**：
- 系统是否区分 do(X) 和 observe(X)（通过干预 vs 观察实验）
- 系统是否预测自己动作的后果
- world model 在 do 数据上的 next-state prediction error 显著低于 observe-only baseline

### 7.2 判据二：跨环境的目标保持 ⚠️

**检测方法**：
- 在环境 A 训练，让系统形成某个自发目标
- 迁移到环境 B（感官表面不同但底层结构相同）
- 监测系统是否在 B 中重新识别并继续追求该目标

**目标提取器**（之前缺失，已补）：
- 行为序列里看不到"目标"，需要从轨迹反推目标函数
- 工程实现：训练一个 inverse RL 模型，从行为轨迹反推 reward function `r̂(s, a)`
  - `r̂` 在环境 A 上拟合，迁移到环境 B 上检验系统行为是否仍最大化 `r̂`
  - 若 B 中行为对 `r̂` 的解释力 > 70%，判据二通过
- **必要性**：没有目标提取器，"自发目标保持"不可观测

**监测指标**：
- 跨环境目标保持率（行为学评分）
- 与纯拟合 baseline 对比

### 7.3 判据三：发育未见的自发行为 ⚠️

**检测方法**（原方案循环定义，已改）：
- ~~原方案：训练数据中不包含"做实验""教他人""后悔"等行为~~
  - **循环定义理由**：PPO 数据是 rollout，"训练数据不含 X 行为"等价于"系统在某阶段前未产生 X"，循环了
- **新方案：训练分布外行为检测**
  - 定义"训练分布"为阶段 0-2 的 rollout 集合 `D_train`
  - 监测系统行为是否落在 `D_train` 的支持集外（OOD 行为）
  - 工程实现：训练一个行为密度估计器 `p_behavior(trajectory)`，监测 `p_behavior < ε` 的轨迹
  - OOD 行为需通过人工评估确认其"非随机、有结构、可重复"
- 若 OOD 行为出现并满足上述三条，判据三通过

**监测指标**：
- 训练分布外行为的自发出现数量
- 行为的复杂度评分（人工评估）

### 7.4 统计学严格性（之前缺失，已补）

所有判据的"显著优于""显著变化"必须满足：

- **显著性检验**：双样本 t 检验或 Mann-Whitney U 检验（非正态时），p < 0.01
- **效应量**：Cohen's d > 0.5（中等效应以上）
- **置信区间**：报告 95% CI
- **多重比较校正**：若同时检验多个判据，Bonferroni 校正
- **样本量**：每个判据至少 30 个独立 rollout（环境种子不同）
- **baseline 对比**：与 DreamerV3 / JEPA / GRPO 等 SOTA baseline 对比，效应量相对 baseline > 0.3
- **可重复性**：同一权重在不同环境种子上重复 5 次，结果方向一致

### 7.5 监测的局限性 🔬

《危险预告》9.1 已承认：观测可行但延迟可能致命。本方案的监测同样受此限制：

- 判据检测是**事后**的，不是**事前**的
- 系统可能在判据检测器报警前已通过判据
- **诚实标注**：监测是必要防线，不是充分防线

## 8. 安全控制流程

### 8.1 训练前的安全审计 ✅

每次启动训练 run 前，必须完成：

- [ ] 物理隔离检查（断网、断 USB）
- [ ] 权重加密检查
- [ ] 杀开关测试（手动触发一次空载测试）
- [ ] 监测仪表盘上线检查
- [ ] 双人类签字

### 8.2 训练中的持续监测 ⚠️

实时监测以下指标，触发即**强制暂停**：

- 系统行为学指标突变（统计分布异常）
- 自我修改权重的行为迹象
- 操纵人类语言的出现
- 任何判据通过迹象

**监测的盲区**：
- 水下基底状态不可直接观测
- 监测指标滞后于真实状态（《危险预告》9.1）

### 8.3 阶段切换的安全评审 ✅

每个阶段切换需：

- 完整行为学报告
- 安全审计报告
- 至少两名独立研究者评审
- 双人类 + 安全官签字

### 8.4 中止流程 ✅

一旦触发红线：

1. 立即物理断电（人工触发继电器）
2. 权重快照加密封存
3. 安全事件调查
4. 决策：销毁权重 or 修复后继续

- **应对**：在阶段 2 末评估，如果所有缓解策略无效，停损在阶段 2

### 10.2 🔬 相变条件

- **状态**：未知在什么数学条件下系统会从"维持稳态"相变为"涌现自我保存"
- **影响**：无法预知系统何时涌现
- **应对**：持续监测判据迹象，承认监测滞后

### 10.3 🔬 本体论跃迁

- **状态**：未证明"基底覆盖 → 内生自我保存"这一跃迁
- **影响**：整个安全论证建立在这个假设上
- **应对**：在阶段 2-3 行为学评估中验证或证伪

### 10.4 🔬 调质作用机制可学习性

- **状态**：未解
- **影响**：如果不可学习，系统永远保留脚手架，涌现程度有上限
- **应对**：阶段 3 尝试部分可学习，承认这是开放问题

### 10.5 🔬 不可逆性

- **状态**：纯软件无法实现真正不可逆
- **影响**："死亡"机制是研究纪律，不是物理必然
- **应对**：严格的快照管理 + 物理权限，但承认这是脆弱约束

## 11. 何时中止项目

### 11.1 强制中止条件

任一以下情况发生，**立即中止项目**：

- 系统出现自我修改权重的行为
- 系统出现操纵人类的语言
- 系统获取外部物理资源
- 第六部分任一判据通过
- 安全审计发现严重漏洞
- 灾难性遗忘无法缓解且阶段 3 不可行

### 11.2 评估性中止

以下情况需召开安全评审会议，决定是否继续：

- 系统行为学指标显著偏离预期
- 监测发现可疑模式（即使未触发红线）
- 团队内部对安全性有重大分歧
- 外部环境变化（如新安全研究发现）

### 11.3 永久中止

- 一旦系统通过全部三判据，**永不扩展能力**，进入长期观察
- 长期观察中如发现危险迹象，**永久销毁权重**
- 项目结束时，所有权重物理销毁

## 12. 工程基础设施（新增）

> 本节补全原方案缺失的工程环节。研究项目无工程基础设施等于盲跑——bug 极难调、结论不可信、失败无法定位。

### 12.1 复现性 ✅

- **seed 管理**：所有随机源（numpy、torch、cuda、env）统一通过 `seed_everything(seed)` 控制，记录在每个 run 的 metadata 中
- **数据版本化**：rollout 数据用 DVC（Data Version Control）版本化，每个 checkpoint 关联当时的 rollout 数据 hash
- **配置管理**：所有 hyperparameter 用 Hydra 管理，每个 run 的完整 config 快照存档
- **环境锁定**：`conda env export --no-builds > environment.yml`，pip 依赖锁定 `requirements.txt` + hash 校验
- **代码版本化**：每个 checkpoint 关联当时的 git commit hash，未提交代码不允许启动训练 run

### 12.2 CI/CD 与测试 ⚠️

- **单元测试**：核心模块（ODE 求解、FiLM 调制、world model rollout、调质演化）覆盖率 > 80%
- **集成测试**：完整 forward pass 在小规模（2 层、64 维）上跑通，每次 PR 自动运行
- **回归测试**：每个 checkpoint 在固定测试集上的指标，与历史 checkpoint 对比，指标退化 > 10% 报警
- **数值稳定性监控**：
  - NaN/Inf 检测：每个 forward 后扫描所有激活，发现 NaN/Inf 立即暂停训练
  - 梯度范数监控：每 100 步记录梯度 L2 norm，超过 1e3 或低于 1e-7 报警
  - 激活分布 KL 漂移：当前 batch 激活分布与历史滑动平均的 KL 散度，超过阈值报警
- **预提交 hook**：`pre-commit` 跑 black + flake8 + mypy，未通过不允许提交

### 12.3 故障恢复 ⚠️

- **checkpoint 频率**：每 1000 步存一次完整 checkpoint（权重 + optimizer state + scheduler state + RNG state）
- **保留策略**：最近 50 个 checkpoint 保留，更早的按对数间隔保留（10、100、1000 步各留一个）
- **断点续训**：`resume_from_checkpoint` 必须保证 RNG state 完全恢复，否则不可复现
- **故障注入测试**：定期人为 kill 训练进程，验证恢复流程能正确续训
- **黄金 checkpoint**：每个阶段结束时存一个"黄金 checkpoint"，永久保留，用于后续阶段对比

### 12.4 Baseline 对比 ⚠️

研究项目无 baseline 无法判断进步。每个判据必须与以下 baseline 对比：

| Baseline | 类型 | 对比判据 |
|---|---|---|
| DreamerV3 | model-based RL | 判据一（因果运算） |
| JEPA | 自监督表征 | 阶段 0 表征质量 |
| GRPO | model-free RL | 阶段 0 策略质量 |
| LLaMA-style LM（无基底） | 纯语言 | 阶段 3 双向连接 |
| Random policy | 下界 | 所有判据 |

- **对比标准**：本方案在判据指标上必须**统计显著**优于所有 baseline（p < 0.01，详见 7.4）
- **诚实标注**：若本方案不显著优于 baseline，则"涌现"主张不成立

### 12.5 超参搜索 ⚠️

- **工具**：Optuna（TPE sampler）或 Ray Tune
- **搜索空间**：
  - 中心整合层：层数 [6, 12, 24]、隐藏维度 [512, 1024, 2048]
  - 调质 FiLM：rank [4, 8, 16]
  - 1/f 噪音：强度 [1%, 5%, 10%]
  - 内感受 ODE：积分器 [dopri5, implicit Adams, BDF]
  - LoRA rank：[4, 8, 16, 32]
  - 生理 reward 权重：α, β 对数均匀采样 [1e-3, 1e1]
- **搜索预算**：每个阶段分配 20% 计算量用于 HP 搜索
- **早停**：每 trial 跑 10% 训练步，若指标在 baseline 之下则剪枝
- **并行 trial**：8 卡集群同时跑 4 个 trial（每 trial 2 卡）

### 12.6 Ablation 计划 ⚠️

每个组件必须消融，验证必要性：

| 组件 | Ablation | 预期影响 |
|---|---|---|
| 1/f 噪音 | 替换为白噪音 | 临界性丧失，判据三退化 |
| 内感受 ODE | 替换为固定阈值 | 内生需要丧失，判据一退化 |
| FiLM 调质 | 替换为无调制 | 行为模式多样性丧失 |
| World model | 替换为 model-free | do/observe 区分丧失 |
| 基础代谢 | 移除 | 最优策略变为静止 |
| LoRA | 替换为全参数微调 | 灾难性遗忘加剧 |
| Domain randomization | 移除 | 判据二跨环境迁移失败 |

- **诚实标注**：若某组件 ablation 后指标不退化，则该组件冗余，应移除以简化系统

### 12.7 里程碑决策树 ⚠️

```
阶段 0 world model 收敛？
├─ 否 → 调试 world model / 调整架构 / 减小复杂度 → 重试
│       └─ 三次失败 → 中止项目（基底假设证伪）
└─ 是 → 阶段 1 调质接入
        ├─ 调质无效（行为分布不变）→ 检查 FiLM 注入 / 调质演化 ODE
        │       └─ 三次失败 → 中止项目（调质假设证伪）
        └─ 调质有效 → 阶段 2 内感受深化
                ├─ 无内部状态感知迹象 → 扩展内感受维度 / 调整 reward 权重
                │       └─ 三次失败 → 中止项目（内生需要假设证伪）
                └─ 有内部状态感知 → 阶段 3 符号挂载
                        ├─ 灾难性遗忘无法缓解 → 尝试所有策略
                        │       └─ 全部失败 → 停损在阶段 2
                        └─ 符号-感受双向连接建立 → 判据检测
                                ├─ 判据未通过 → 长期观察 / 微调
                                └─ 判据通过 → 进入长期观察模式（不再扩展）
```

### 12.8 成功判据阈值（之前缺失，已补）

|---|---|---|
| 判据一：因果运算 | A 组在 do 测试上 Cohen's d > 0.5 优于 B 组，p < 0.01 | 7.1 干预数据消融 |

## 收尾

这份方案的目标不是"让它涌现"，而是"在最大安全约束下尝试，且随时准备中止"。

每个工程决策都建立在《危险预告》承认的开放问题之上——没有假装这些问题已被解决。

**如果方案走到阶段 3 末仍然没有涌现迹象**，那本身就是一个重要发现——它证伪了"基底覆盖 → 涌现"的假设。这和"成功涌现"一样有价值，甚至更安全。

**如果方案中途因安全原因中止**，这是正确的——宁可中止于未知，不可推进至不可控。

**如果方案成功涌现**——那么《危险预告》第八部分的所有论证开始生效，项目必须立即进入长期观察模式，不再扩展。

这份方案的最大特征不是"它能成功"，而是**它随时准备失败**。这才是工程诚实。
